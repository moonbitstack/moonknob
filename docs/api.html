moonbitstack/moonknob · @moonknob

A settings record, the flat arguments beside it, and the policy that settles a disagreement. One package, and nothing outside the core library to build it.

The order is this: what the library starts from, then the record, then this call's argument. Wins picks the direction and OnClash says what happens when the two disagree.

typeMerge

Lays what a caller gave over what a function starts from, one setting at a time, and keeps the names of those that disagreed for settle.

test {
  let merge = @moonknob.Merge::new(Extra)
  let timeout = merge.pick("timeout", 30, Some(10))
  assert_eq(timeout, 10)
  assert_eq(merge.names().to_owned(), ["timeout"])
}

enumOnClash

What to do when a setting is given twice with different values.

The same value given twice is not a clash: there is only one answer, and nothing is reported.

pub(all) enum OnClash[T] {
  Ignore
  Warn((String) -> Unit)
  Panic
  Handle((Clash[T]) -> T)
}
IgnoreTake what wins says and say nothing. What most libraries do.
Warn((String) -> Unit)Take what wins says and pass one line about it to the function, a logger's warn for instance. The library itself prints nothing.
PanicAbort, for where two answers are a mistake in the program rather than a choice about configuration.
Handle((Clash[T]) -> T)Pass the clash to the function and take what it returns.

fnOnClash::settle

pub fn[T] OnClash::settle(
  self : OnClash[T],
  base : T,
  merged : T,
  names : Array[String],
  site : String,
) -> T

What a function ends up with, given what it started from, the two laid together, and the settings that disagreed. With no names there was no clash, and merged comes back whatever self is.

site is the call and its two sources, for the warning and the abort: "jwt.verify: policy and arguments".
